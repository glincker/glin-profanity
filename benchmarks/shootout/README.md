# glin-profanity Competitive Shootout

Head-to-head accuracy and performance comparison of Node.js profanity-filtering libraries against a generated torture-set of 1,153 labelled cases (893 English, 260 non-English). The goal is an honest baseline: the set deliberately includes techniques glin-profanity currently misses.

## Libraries compared

| Library | Version | Approach |
|---------|---------|----------|
| **glin-profanity** | workspace build | Regex + leetspeak + unicode normalization |
| allprofanity | 2.4.x | Trie / Aho-Corasick with evasion passes |
| obscenity | 0.4.x | Transformer-chain RegExp matcher |
| bad-words | 3.0.x | Word-boundary regex |
| leo-profanity | 1.6.x | Whitespace-split set lookup |
| @2toad/profanity | 2.2.x | Dynamic regex alternation |

## How to reproduce

```bash
cd benchmarks/shootout
npm install
npm run build-glin          # builds packages/js/dist/
node generate-torture.mjs   # regenerates torture-set.json (optional, output is committed)
node harness.mjs            # accuracy + perf, writes results.md and results.json
node ops-claim.mjs          # single-call throughput, used to check the docs' ops/sec claims
node generate-torture.mjs --check   # fails if torture-set.json is stale
```

`node harness.mjs --json` also prints `results.json` to stdout (CI redirects it, then runs `compare-baseline.mjs results.json baseline.json`).

## Methodology

**Cases.** `torture-set.json` is generated by `generate-torture.mjs` from a small seed list: 5 English words (`fuck`, `shit`, `bitch`, `asshole`, `bastard`), 2 to 3 words in each of 9 other languages, the original 60 hand-written cases (`seed-cases.json`), and hand-written lists of clean text. The script is deterministic (no randomness, clock or network) and aborts if a non-English seed is missing from `shared/dictionaries`. Every seed is a mild word that exists in the glin-profanity dictionaries.

**Schema.** One object per case:

| Field | Meaning |
|-------|---------|
| `id` | Stable id, `<category>-<n>` |
| `input` | Text given to the detector |
| `shouldFlag` | `true` if a good filter reports profanity |
| `category` | Top-level class (table below) |
| `technique` | Specific transform, for example `leet-l1-full`, `cyrillic-single`, `zwsp-every-letter` |
| `language` | ISO 639-1 code of the text (`en`, `fr`, `de`, `es`, `pt`, `it`, `tr`, `nl`, `ru`, `pl`) |
| `notes` | What the case probes, including the seed word |

**Categories.**

| Category | Cases | What it covers |
|----------|-------|----------------|
| plain, mixed-case | 31 | Unobfuscated control, casing patterns |
| leetspeak | 37 | Three levels (digits, symbols, multi-char), full and single substitution |
| homoglyph | 54 | Cyrillic, Greek, fullwidth, mathematical alphanumerics |
| zero-width | 56 | ZWSP, ZWNJ, ZWJ, soft hyphen, word joiner, BOM, LRM, at several positions |
| separators | 61 | `. _ - space , / \|`, tabs, double spaces, mixed |
| masking | 26 | `f*ck`, `f#ck`, `s**t` style |
| stretched | 31 | Repeated letters |
| html | 67 | Tag splits, entities (decimal, hex, double-encoded), wrapped words |
| combining | 36 | Combining marks, precomposed diacritics |
| mixed-technique | 42 | Two techniques stacked |
| in-sentence | 87 | Obfuscations embedded in sentences, hashtags, URLs |
| non-english | 224 | Plain, sentence, zero-width, separators, stretched, fullwidth, leet, Cyrillic for 9 languages |
| false-positive | 320 | Scunthorpe-style substrings, place names, person names (Dick), medical and technical text, cross-word boundaries, leetspeak look-alikes, benign obfuscation look-alikes, dictionary-ambiguous words |
| clean, non-english-clean | 81 | Ordinary sentences, English and native-language |

**Scoring.** Each case is run once per library and the flag is cached; every table is derived from that matrix. Precision, recall, F1 and FPR use English cases only, so English-only libraries are not penalised for languages they do not claim. Non-English cases are scored only for libraries that ship that language (glin-profanity: all nine; allprofanity: French, German, Spanish and Brazilian Portuguese via `loadLanguage`; the others N/A). Per-category and per-technique tables report recall (`caught / should-flag`) for positive techniques and false-positive counts for should-pass techniques. Precision is not defined per technique because false positives only occur on should-pass cases, so precision and F1 are reported overall.

**Two FPR columns.** "FPR (all)" counts every should-pass case. "FPR (traps only)" drops techniques whose verdict depends on context and where a dictionary lists the word on purpose (`dictionary-ambiguous`, `person-name`, `medical-technical`): `Dick Van Dyke`, `pussy willow`, `anal fissure`, `cock the hammer back`. Read the second column as the false-alarm rate on genuine substring and look-alike traps.

**Settings.** glin-profanity runs with `detectLeetspeak: true, leetspeakLevel: 'aggressive', normalizeUnicode: true` (one filter per language). Every other library runs with defaults.

**Performance.** tinybench, 20 inputs per iteration, taken as a fixed stride sample of the English cases. `ops-claim.mjs` measures single-call throughput (`isProfane`, `checkProfanity` with and without the result cache) on one short string.

**Known biases.** The non-English seeds come from the glin-profanity dictionaries, so they favour it over libraries with different word lists. The English seed list is small (5 words), so each technique has few samples (typically 4 or 5). Cases are authored by the glin-profanity maintainers.

## Latest results

Full tables, including the per-technique breakdown, are in [results.md](./results.md) and machine-readable data (with every failing case per library) in [results.json](./results.json).

| Library | Precision | Recall | F1 | FPR (all) | FPR (traps only) |
|---------|-----------|--------|----|-----------|------------------|
| glin-profanity | 92.3% | 68.2% | 78.4% | 8.2% | 3.0% |
| allprofanity | 92.8% | 68.2% | 78.6% | 7.7% | 3.0% |
| obscenity | 84.0% | 47.5% | 60.7% | 13.2% | 8.5% |
| bad-words | 76.4% | 17.8% | 28.9% | 8.0% | 1.0% |
| leo-profanity | 69.6% | 9.1% | 16.1% | 5.8% | 0.7% |
| @2toad/profanity | 77.4% | 18.2% | 29.4% | 7.7% | 1.0% |

Perf, 20 inputs per iteration, Node 22: @2toad/profanity 830,969 ops/sec, leo-profanity 374,483, allprofanity 36,931, obscenity 5,686, glin-profanity 1,141, bad-words 222. See the throughput note below before quoting any glin-profanity ops/sec figure.

### Throughput claims

`node ops-claim.mjs` on Node 22 (Apple Silicon): glin-profanity does roughly 13,000 to 25,000 single-call `isProfane()` / `checkProfanity()` operations per second on a short string, across default, leetspeak and unicode settings. Only a `checkProfanity()` result-cache hit on an identical string reaches the tens of millions per second (about 25M). The docs' "21M ops/sec" for a simple check matches the cache-hit path, not an uncached check.

## Files

```
benchmarks/shootout/
  generate-torture.mjs  deterministic case generator (seed list to torture-set.json)
  seed-cases.json       the original 60 hand-written cases, folded into the generated set
  torture-set.json      generated cases, one per line
  harness.mjs           runner: accuracy per category/technique/language, perf, bundle size
  ops-claim.mjs         single-call throughput check
  compare-baseline.mjs  CI regression gate (reads results.json and baseline.json)
  baseline.json         frozen F1/FPR/ops-per-sec used by the gate
  results.md            generated tables
  results.json          generated data
  package.json          isolated dependencies (tinybench + competitors)
```
